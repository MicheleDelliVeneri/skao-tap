skao-tap deployed.

TAP base URL (in cluster):
  http://{{ include "skao-tap.fullname" . }}-tap-api:{{ .Values.tapApi.port }}/tap
{{- if .Values.ingress.enabled }}
External:
  http://{{ .Values.ingress.host }}/tap
{{- end }}

Try it:
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "skao-tap.fullname" . }}-tap-api {{ .Values.tapApi.port }}
  curl "http://localhost:{{ .Values.tapApi.port }}/tap/sync" \
    --data-urlencode "LANG=ADQL" \
    --data-urlencode "QUERY=SELECT TOP 5 * FROM ska.continuum_sources"

Run the chart smoke test:
  helm test {{ .Release.Name }} -n {{ .Release.Namespace }}

{{- if or .Values.horizontalAutoscaling.tapApi.enabled .Values.horizontalAutoscaling.tapExecutor.enabled }}

Autoscaling is on, so `replicas` is no longer what runs:
{{- if .Values.horizontalAutoscaling.tapApi.enabled }}
  tap-api       {{ .Values.horizontalAutoscaling.tapApi.minReplicas }}-{{ .Values.horizontalAutoscaling.tapApi.maxReplicas }} pods, on {{ .Values.horizontalAutoscaling.tapApi.targetCPUUtilizationPercentage }}% CPU
{{- end }}
{{- if .Values.horizontalAutoscaling.tapExecutor.enabled }}
  tap-executor  {{ .Values.horizontalAutoscaling.tapExecutor.minReplicas }}-{{ .Values.horizontalAutoscaling.tapExecutor.maxReplicas }} pods, one per {{ .Values.horizontalAutoscaling.tapExecutor.queuedJobsPerReplica }} queued jobs ({{ .Values.horizontalAutoscaling.tapExecutor.scaler }})
{{- end }}
A fresh install starts at one pod per service and is scaled up from there, so
give it a minute before reading the pod count.
  kubectl -n {{ .Release.Namespace }} get hpa
{{- end }}

NOTE: with more than one executor pod — whether from tapExecutor.replicas or
from an autoscaler's maxReplicas — or multi-node scheduling, the results
volume must use a ReadWriteMany-capable storage class (results.accessModes).
